# 邮箱绑定与密码找回

注册不强制绑定邮箱。用户登录后在“我的 → 账号设置”验证当前密码和邮箱验证码完成绑定，之后才能通过登录页的“忘记密码”找回账号。

## 邮件配置

正式参数放在 `/etc/hex-mahjong.env`，保持 root:root、600 权限；不要将真实授权码写入源码、文档、命令行参数或 GitHub。QQ SMTP 配置为：

```ini
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=your-qq-number@qq.com
SMTP_PASS=your-smtp-authorization-code
MAIL_FROM=your-qq-number@qq.com
MAIL_PUBLIC_BASE_URL=https://example.com/hex-mahjong/
```

`MAIL_PUBLIC_BASE_URL` 使用用户可访问的真实地址并以斜杠结尾。未设置时由固定的 `ALLOWED_ORIGINS` 和 `HEX_BASE_PATH` 生成，不能由请求 Host 决定。生产地址必须为已允许的 HTTPS 来源。不要把 localhost 地址发给正式用户。

本地可在被 Git 忽略的 `.env` 填写测试发信配置，然后运行 `node --env-file=.env server.mjs`；普通 `npm start` 不会自动读取 `.env`。未配置完整 SMTP 时，注册和登录保持可用，邮箱发送接口提示服务未开放。

程序更新需要安装新依赖 `npm ci --omit=dev --ignore-scripts`，保留现有独立账号数据库和服务器环境文件，再切换发布版本。首次启动自动为旧库增加邮箱、验证凭据与发送限额结构。部署前做一致性数据库备份；服务重启会结束内存房间。

## 规则与保护

- 一个邮箱只能绑定一个账号；验证成功前不修改旧绑定，更换成功后通知旧邮箱。
- 六位验证码 10 分钟有效，最多尝试 5 次；只适用于发起验证的账号、当前会话和目标邮箱。发送成功后才启用凭据。
- 重置令牌为 32 字节密码学随机值，15 分钟有效且只能消费一次。令牌在链接 fragment 中传递，打开页面后从地址栏移除；不会作为页面 URL 的查询参数进入服务日志。
- 验证码与令牌仅存摘要。密码重置事务同时更新密码、消费凭据并撤销全部会话；收藏和卡池不受影响。
- 修改密码、更换邮箱使旧凭据失效；异步密码计算后会再次核对凭据和账号状态，防止重复消费或竞态覆盖。
- 发信间隔至少 60 秒；默认全站 60 封/小时、每 IP 10 封/小时、每邮箱 6 封/小时、绑定每账号 6 封/小时。申请次数统一计入持久化限额，发送失败和未绑定邮箱申请也计数。
- 找回申请对未知邮箱和已绑定邮箱返回相同内容，未知邮箱不会实际发信。SMTP 队列最多 2 个并发任务、4 个等待任务，失败不启用新凭据。
- 正式 SMTP 使用 TLS；本地无 TLS 仅允许开发模式下的 loopback 测试接收器。邮件服务故障不改变用户的密码或已有邮箱绑定。

## 验证

`npm run test:email` 在内存账号库和临时目录中使用本地 SMTP 接收器，不连接 QQ 邮箱、不向真实用户发信。验证绑定、找回、错误/过期/重放、发送失败、持久化限额、旧库迁移及私人数据保留。

已通过完整回归和 320/390 像素手机、1280 像素桌面浏览器自检，记录见 `artifacts/email-binding/README.md`。首次打开邮件链接和在已打开的页面中进入邮件链接都能读取重置凭据并立即清理地址栏。

上线后可由用户在自己的账号页面主动发验证码，检查收件箱或垃圾邮件，再完成绑定并验证找回。不要在服务日志记录邮件正文、验证码或重置链接。

## 界面设计

沿用个人中心深蓝底、青色辅助动作和金色主按钮。账号设置增加一行邮箱状态，未绑定明确说明不能找回；绑定使用原生弹窗，验证码输入与重发按钮并排，底部取消在左、验证在右。登录页保留两个注册必填项，找回单独显示邮箱输入，重置单独显示两次新密码输入，不把所有表单堆在同一页。

重点检查 320～390 像素手机宽度、验证码重发/错误状态、已绑定脱敏状态、重置成功状态和键盘/弹窗焦点。此局部界面沿用已有设计，由主 Agent 自检，不另做视觉方向探索或独立评审。
