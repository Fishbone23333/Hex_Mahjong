# 账号版安全部署与恢复

这些文件提供一套可自行调整的 Nginx/systemd 部署示例。请根据实际域名、路径和服务账号修改环境文件与 unit；不要把真实环境文件、数据库、密钥或部署记录提交到 Git。

## 目录与权限

| 路径 | 所属与权限 | 用途 |
| --- | --- | --- |
| `/opt/hex-mahjong` | root:root，目录 755、文件 644 | 程序；服务账号不可修改 |
| `/var/lib/hex-mahjong` | hex-mahjong:hex-mahjong，700 | SQLite、WAL、SHM；不对外提供 |
| `/var/backups/hex-mahjong` | hex-mahjong:hex-mahjong，700 | 一致性备份；默认保留最近 14 份 |
| `/etc/hex-mahjong.env` | root:root，600 | 正式配置；与发布包分离 |

服务账号无登录 Shell，不加入 sudo；原 ubuntu SSH 管理账号保留。Node 至少 22.16；现有腾讯云 22.22.2 满足要求。不要设置 MemoryDenyWriteExecute，以免阻止 V8/WebGL 依赖的正常运行。

首次安装账号及数据目录：

```sh
sudo useradd --system --user-group --home-dir /var/lib/hex-mahjong --shell /usr/sbin/nologin hex-mahjong
sudo install -d -o root -g root -m 755 /opt/hex-mahjong
sudo install -d -o hex-mahjong -g hex-mahjong -m 700 /var/lib/hex-mahjong /var/backups/hex-mahjong
```

若账号已存在，先通过 `id hex-mahjong` 确认，无需重复创建。

## 发布包与切换

1. 本地先运行 `npm test`，再运行 `npm run release:prepare`。该命令只复制白名单文件到新目录，不复制数据库、环境变量、密钥、日志、原型或测试服务器。核对 `release-manifest.json`。
2. 上传到服务器一个新的暂存目录，在主项目和 `artifacts/bai-zhe-shi-chen/web` 分别执行 `npm ci --omit=dev --ignore-scripts`。不要对整个本地工作区使用 `rsync --delete`；不上传 `data/`。
3. 修改 `hex-mahjong.env.example` 中来源、Cookie 路径等正式参数，安装为 `/etc/hex-mahjong.env`，权限 600。代理仍是 `/hex-mahjong/` 时使用示例路径和专用 Cookie 名。生产禁止 HTTP 来源；结算概率维持 0.03。更换 Cookie 名会要求旧登录用户重新登录。
4. **切换前**保存当前程序目录、systemd unit 与 Nginx 配置。若有旧账号数据库，先用 `backup-database.mjs` 备份到独立路径；不要在旧 writer 运行时单独复制 `.sqlite`。备份后再停止旧服务，将一致性数据库恢复到 `/var/lib/hex-mahjong/hex-mahjong.sqlite` 并设为 600。
5. 停止旧服务再替换 `/opt/hex-mahjong` 的代码内容，将所有代码文件设为 root:root、只读给服务账号。安装 `deploy/hex-mahjong.service` 和备份／监控 unit，执行 `systemctl daemon-reload`。**重启会结束内存中的房间，请在没有进行中的牌局时切换。**
6. Nginx 的 http 区域引入 `nginx-http-limits.conf`；安装 `hex-mahjong-proxy.conf` 为 `/etc/nginx/snippets/hex-mahjong-proxy.conf`；仅替换旧麻将 location 为 `nginx-locations.conf`。保留另一应用的配置。执行 `sudo nginx -t`，成功后 reload。
7. 启动网页服务，验证 HTTPS、WSS、账号登录、游客入房、私人池同步、计时音效和闪卡，确认 Secure、Cookie Path、API no-store 实际生效。执行一次备份后启用备份／监控 timer。

```sh
sudo systemctl enable --now hex-mahjong
sudo systemctl start hex-mahjong-backup.service
sudo systemctl enable --now hex-mahjong-backup.timer hex-mahjong-monitor.timer
sudo systemctl start hex-mahjong-monitor.service
sudo systemctl show hex-mahjong -p User -p NoNewPrivileges -p ProtectSystem -p ProtectHome
sudo systemd-analyze security hex-mahjong.service
sudo journalctl -u hex-mahjong -u hex-mahjong-backup -u hex-mahjong-monitor --since today
```

## 备份与恢复演练

`npm run backup` 使用 `node:sqlite` 的备份接口，包含 WAL 中已提交事务，并执行 integrity_check。成功后才清理旧备份，不覆盖已有文件。备份目录必须在站点公开目录之外。服务器备份仍在同一磁盘，**还需把备份下载到管理电脑或已授权的独立存储**；本轮未配置外部存储或上传任何数据。

本地 `npm run test:backup` 已验证原 writer 开着时备份、恢复登录／会话／卡牌／卡池以及防覆盖。上线前还需要针对正式数据做独立演练：将一份备份复制到测试路径，用 `HEX_DB_PATH` 和独立端口启动同版本程序，验证登录、数据数量和用私人池创建房间。不要在测试环境向公网开放正式用户数据。

恢复正式数据时先停服务，保留损坏文件及 WAL/SHM 到独立故障归档，不与恢复库混用。安装备份为正式数据库并设 owner/600，再启动服务。回滚程序时先确认数据库结构兼容，不直接覆盖新数据。当前加固仅增加索引，没有删除或改写原业务表。

## 监控和日志

应用按分钟记录连接数、房间数、内存和事件循环延迟；异常日志只记录分类码，不记录账号密码、Cookie、恢复令牌或私人请求体。每五分钟的监控检查服务重启、内存、磁盘、数据库体积、备份新鲜度和实际 HTTPS；证书低于 48 小时失败退出。失败记录进入 systemd journal，可用 `systemctl --failed` 查看。

如机器未限制 journal 容量，在既有 `/etc/systemd/journald.conf.d/` 配置中评估设置 `SystemMaxUse=200M`、`MaxRetentionSec=14day`。这是整机共享设置，要与另一应用的日志策略一起核对。应用自身每 30 秒最多写 100 条 journal 日志。

监控 timer 和日志**不会自动发消息给你**。外部可用性监测、告警收件人和外部备份存储尚需选定；在配置前不能声称已经具备完整告警闭环。

## 可调产品边界

默认账号上限 5000、私人牌 200、池 30、会话 10，均可配置。每列表响应最多 100 条；工坊分批加载完整内容。数据库+WAL 256 MiB 或磁盘不足 100 MiB 时暂停新增/修改，会保留读取和删除。备份/监控会提前在 200 MiB、剩余 500 MiB 时提示。

卡池搜索一次最多 12000 步、20ms；超预算以 422 拒绝，既有牌局不提交半张结果。上线后应在真实服务器上观察资源指标再调参数，未做公网容量压测。

同成员只允许一个活跃连接，新页面接管旧页面，旧页面不自动抢回。锁屏席位保留 10 分钟并计入四人上限；所有人主动退出立即解散，10 分钟无牌局操作删除的原规则保留。

Cookie 路径只减少无关路径发送，不隔离同源脚本。正式对公众开放仍建议独立域名或子域名。没有现成域名时，不编造域名、DNS 或证书配置，也不贸然启用 HSTS preload。
